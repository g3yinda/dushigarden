## 手机扫码真机调试（同 Wi-Fi）

手机访问 `127.0.0.1` 时指向手机自身；普通服务只监听电脑回环地址，所以原配置只适用于模拟器。真机调试按以下步骤：

1. 手机与电脑连接同一个 Wi-Fi，电脑保持开机且服务持续运行。
2. 停止原来的 `npm start`（Ctrl+C），执行 `npm run dev:phone`。
3. 脚本自动检测电脑的私有 IPv4，启动局域网调试服务，并生成本机 `miniprogram/config.js`。手机使用电脑地址，模拟器仍使用回环地址。该文件包含每次启动的调试访问码，已从 Git 移出；不得上传或公开分享调试包。
4. 在微信开发者工具重新编译，再点击“真机调试”生成新的二维码，用微信扫码。每次重新启动此命令或更换 Wi-Fi 都要重新编译并扫码，旧调试包的地址/访问码可能失效。
5. 在手机中建房、添加 Bot、准备并开局；也可让另一台同 Wi-Fi 手机扫码参与同房。

默认端口 8787。多个网卡可用 `npm run dev:phone -- --host=电脑的同WiFi地址` 指定，脚本只接受本机存在的私网地址。若手机无法访问，先在 Safari 打开终端显示的地址加 `/api/health`，应看到 `ok:true` 与 `phoneDebug:true`。这一步只检查网络通路，不需要输入访问码。打不开时检查同 Wi-Fi、访客网络隔离，以及微信的“本地网络”权限；不要关闭整个防火墙。

开发工具当前已切到公网调试配置（见下一节）；以下为同 Wi-Fi 模式说明，正式微信登录与发布配置仍按下文执行。同 Wi-Fi 调试不使用 AppSecret，也不需要部署公网服务；跨网络朋友联机仍需要 HTTPS 后端。局域网开发 API 要求真实私网来源与本次有效访问码，正式模式禁止这一方式，转发头不会获得开发权限。

`npm start` 会恢复模拟器默认配置；首次下载仓库时普通启动/`npm run check` 会生成默认配置。上线时从 `miniprogram/config.example.js` 复制为 `config.js`，填入正式 HTTPS 地址并关闭本地模式，再跑 `node tools/check.js --release`；发布检查同时拒绝整套真机调试配置。

## 公网后端准备

需要一套能持续运行 Node.js 24 的服务、持久化磁盘和 HTTPS 域名。当前是单进程内存状态加原子 JSON 快照，适合第一轮朋友试玩；不能直接启动多个 worker 或多个实例共享同一快照。容器重建必须保留数据卷。正式扩大规模前再迁移数据库与跨实例同步。

复制 `.env.example` 为本机私有 `.env`，设置以下变量：

| 配置 | 说明 |
|---|---|
| NODE_ENV | 正式环境必须为 production；启用真实微信登录并关闭开发身份 |
| WX_APP_ID | wx529cf19d338aebcf |
| WX_APP_SECRET | 在部署环境填写，只存后端密钥配置，不进入客户端、仓库或聊天 |
| HOST / PORT | 直接部署通常使用 127.0.0.1 / 8787，并由 HTTPS 反向代理转发 |
| DATA_FILE | 可写的持久化路径，例如 /data/boomcat/state.json |

`.env` 不由 `npm start` 自动加载，部署时可使用：

```sh
node --env-file=.env server/index.js
```

反向代理应支持至少 30 秒的读取等待，长轮询正常等待最长 20 秒；API 响应不缓存。健康检查是 `GET /api/health`，生产响应的 mode 应为 `wechat`。服务端将 `wx.login` 的 code 交给微信换取身份，客户端不能自己声明 openid。

也提供了 Dockerfile，已在腾讯云实际构建并启动公网调试容器，当前镜像版本见 [部署状态](10-公网测试与发布状态.md)。使用容器时 HOST 应设为 `0.0.0.0`；示例 `.env` 内的 HOST 会覆盖镜像默认值。容器数据目录 `/data` 必须挂载持久化卷并对 node 用户可写。不要把 `.env` 中的密钥写进 Dockerfile。

## 当前房间设置验证

建房默认否定 10 秒，可选 10 / 20 / 30 秒或不限时。再开沿用设置，进行中不可修改。升级前旧房间保留原 5 秒，请新建房查看新设置。房主点左上角退出，再选“关闭整个房间”，二次确认后全员返回大厅，可立即另建房；“仅自己离开”保留原托管行为。

更新后先重启 `npm run dev:phone` 后端，再在微信开发者工具重新编译并重新生成真机调试二维码。重启会生成新的本机访问码，旧调试包需要重新扫码；配置与对局快照不上传 GitHub。

否定选择固定在页面底部的打出/抽牌操作栏上方，显示“是否选择否定”，不再自动弹窗。点击“本次不出”由服务器确认，本轮不可改为打出，本人停止计时并显示等待人数；全员确认或超时后结算，选完可提前结束。没有否定自动完成、两按钮置灰，不需点击不出，Bot 同样确认，不泄露别人手牌。循环开关开启时每张否定开启新层，其他仍持否定者可以重新选择；关闭时首张否定直接取消。公网模式更新后重新编译并生成真机调试二维码获取新包，无需同 Wi-Fi；仅 dev:phone 局域网模式需要同 Wi-Fi。
