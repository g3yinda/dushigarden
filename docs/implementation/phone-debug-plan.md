# 同 Wi-Fi 真机调试修复计划

2026-09-30。根因已核对：客户端指向 127.0.0.1，服务只监听回环，开发身份和 Bot 仅接受回环来源。手机扫码后访问的是手机自身。

- 新增 `npm run dev:phone`：自动找到电脑当前私有 IPv4，启动可从局域网访问的开发服务，同时保留回环入口；每次启动生成调试访问码。
- 手机与模拟器使用不同请求地址。生成的客户端配置留在本机并排除 Git；缺失配置时普通启动/检查自动生成回环默认配置。
- 局域网开发接口要求真实 socket 私网来源与有效调试访问码，不信任转发头；正式微信模式完全不接受此访问方式。Bot 同样遵守此边界。
- 先写访问边界、客户端平台选址/请求头和 HTTP 流程回归，观察失败，再实现并全量验证；直接检查当前 LAN 地址的健康、登录、建房及 Bot 接口。
- 保留用户当前对局数据；运行与真机调试步骤写入文档。编译小程序后请用户重新扫码并反馈手机实际结果，不能用电脑请求代替真机成功证据。

## 完成证据

114 项回归与常规检查通过；真实 LAN 登录/建房/Bot HTTP 200，未携带访问码被拒绝。重新连接的 iPhone 真机调试直接显示电脑 LAN 地址的房间指令 HTTP 200 和正常同步。原配置和正式模式保持隔离，端口冲突不覆盖当前有效配置。
