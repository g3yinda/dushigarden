# 本地验证 Bot 实施计划

> 历史材料：本文件保留当时的设计、计划或验收，不作为当前行为说明。当前规则、UI、交付和待办见 [v0.9.5 当前状态](../00-当前状态与文档索引.md)。

2026-09-30，用户明确要求上传首版并添加单人本地 Bot，沿用已批准的界面风格。

**目标：** 用户在浏览器或微信模拟器创建房间后，可以添加 1–4 只验证 Bot，独自完成准备、出牌、特殊阶段、结算与再开。

**架构：** Bot 是本地 RoomService 中的明确标记席位；BotRunner 在服务端定时循环中使用玩家投影和普通指令，不能读取对手手牌或权威牌库。正式微信模式不创建 runner，接口拒绝添加 Bot。Bot 随快照恢复，真人全员离线仍触发原有中止策略。

**技术栈：** 现有 Node.js 24、原生小程序与浏览器端，不增加外部模型/API、依赖或收费服务。

## 接口与行为约定

`POST /api/rooms/:code/bots`，请求 `{count, respondNope, revision, commandId}`；count 整数 1–4，respondNope 布尔，使用现有指令去重机制。响应普通 RoomView，追加 `isBot` 标记。真人只能在准备阶段移除 Bot；再来一局保留 Bot 并自动准备。

Bot 每个普通回合最多主动出一次牌（含组合）；暂停重连与重启保留该回合记录，下一回合重新计算。Bot 思考约 1.5 秒；响应否定可关闭以方便验证牌的实际效果。Bot 能使用功能牌、同名对子/三张、交牌、拆弹和插回；决策只依据自己手牌、公开牌数和自己的预知结果。开局随机牌库，不为 Bot 保底胜利，不改变正式规则与倒计时。

测试 Bot 不提供强度承诺，不能替代真人联机与性能验收。用户退出/全部真人断线后 Bot 暂停，原有 5 分钟中止仍有效；Bot 不占用微信登录身份或在生产环境开放。
