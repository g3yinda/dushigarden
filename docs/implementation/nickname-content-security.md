# 自定义昵称内容安全整改｜2026-10-08

## 目的与实现范围

用户收到微信平台关于用户生成内容缺少过滤机制的通知，本次补齐自定义昵称的服务端审核。不改变已批准的界面、卡牌规则、微信登录或 Bot 权限。此项是第一阶段收尾后的定向整改；不表示已部署、已通过微信审核或已经正式发布。

- 首次提交昵称、登录时换昵称、已有会话修改昵称，统一在保存前调用微信 `msgSecCheck` v2，`scene=1`（资料），`content` 和 `nickname` 都传最终要保存的昵称。
- 使用服务端通过 `wx.login` code 换取的 OpenID；改名时校验其与原会话的哈希身份一致。客户端传入的 OpenID、审核记录或“通过”标记均不可信，不能跳过审核。
- 昵称与原来一致：去首尾空格，按现有12个UTF-16代码单元限制截断；额外拒绝非文本及控制/隐藏方向字符。只审核最终存储文本，不允许先审核甲再保存乙。
- 只放行 `errcode=0` 且 `result.suggest=pass`。`risky`、`review` 和 `87014` 均拦截；本项目没有人工复核队列，因此 review 不会自动发布。
- 超时、证书/网络错误、无权限、额度不足和缺失判定均返回“昵称审核暂时不可用，请稍后再试”；不会关闭审核或降级放行。
- 审核失败保留原有资料和房间昵称；新注册失败不创建玩家或会话，不继续建房/加入。
- 服务端存储通过记录（规则版本、已审核昵称、时间、traceId）；同一玩家未修改的已审昵称复用结果，减少额度消耗。修改后必须重新审核。审核标记不返回客户端。
- 日志仅记录 `[nickname-security]`、pass/blocked/unavailable、固定原因、数字错误码及合规格式的 traceId；不记录昵称原文、OpenID、AppSecret、access_token 或微信原始 errmsg/detail/keyword。

涉及文件：`server/content-security.js`、`server/nickname-policy.js`、`server/index.js`、`server/rooms.js`、`miniprogram/pages/home/home.js`、`Dockerfile` 及配套测试。

## 旧昵称与已有对局

正式 `wechat` 服务在开始监听前执行一次兼容迁移。没有有效审核记录的旧昵称暂时改为固定“小猫”，房间座位和游戏玩家同步安全名称；用户在新版输入昵称、建房或加入时重新审核。

旧房间中可能包含旧昵称的公共历史文字统一改为“历史行动（昵称审核升级前）”；事件编号、结构化卡牌事件、手牌、牌堆、输赢与规则数据保留。新房间与新产生的记录不受影响；迁移版本写入快照，重启不会反复清空新历史。已审核昵称记录随现有快照保存。

部署前应备份现有 `/data/state.json` 并避开进行中的对局；备份含玩家数据，只能私下保管。生产仍需单实例/可靠持久化，原有并发实例风险没有在本次修改。**不要直接回滚到不含审核逻辑的旧后端对外提供服务。**

## 云托管上线步骤（本项目推荐路径）

1. 登录微信云托管控制台，选环境 `prod-d2gqiy08z19bd1427`，不要选云开发的 cloudbase 环境。
2. 打开左侧“云调用”，找到“微信令牌权限配置”或“云调用权限配置”。保留原有配置，另起一行添加以下路径并保存：

   ```text
   /wxa/msg_sec_check
   ```

3. 在同一页面确认“开放接口服务”开关已开启。必须先开启再构建新版本，旧版本不会仅因为切开关就自动获得侧车代理。
4. 服务列表进入 `boomcat` → 部署发布 → 新建版本，上传 `output/deploy/boomcat-nickname-security-2026-10-08.zip`。使用根目录 Dockerfile 构建，端口保持 `8787`。
5. 本次 Dockerfile 已设 `WX_CONTENT_SECURITY_MODE=cloudrun`，通过既有 HTTPS + 平台 CA 信任链调用开放接口，无需另填 access_token。若运行变量里有同名字段，请设为 `cloudrun`，不要带反引号/空格。保留原来正常工作的 `NODE_ENV=production`、`BOOMCAT_MODE=wechat`、`HOST=0.0.0.0`、`PORT=8787`、`WX_APP_ID`、`WX_APP_SECRET`、`NODE_EXTRA_CA_CERTS=/app/cert/certificate.crt`；AppSecret仍用于真实登录，不要发送到聊天。
6. 构建部署完成后确认新版本承接全部流量，旧版不再接收请求。不能只看到镜像构建成功就认为昵称审核上线了。
7. 微信开发者工具重新编译本地项目，执行 `npm run check:release` 后上传新的小游戏代码并选为体验版。本次前端也有修改：已有会话改名会提交新的微信登录 code，登录/资料请求超时预算为25秒；**只部署后端、保留旧体验包不够**。新体验版与后端应在同一次维护窗口切换。
8. 关闭手机“开发调试”，重新扫码，用正常昵称创建房间。云端运行日志应看到 `event=nickname_security`、`outcome=pass` 和 traceId；用另一微信账号确认看见的为审核后的昵称。
9. 按微信当前内容安全文档/平台要求进行风险样例验证并留存截图或录屏：提示拒绝、无法建房，已存在昵称不被覆盖，日志出现 blocked。不要通过聊天发送真实秘密、访问令牌或违法内容。本地使用合成返回值测试，不能代替此项真实平台验收。

未上架小程序的官方文档当前标明文本审核额度为100次/天；避免不断更换昵称重复测试。额度不足时本实现会阻断新昵称提交，已审且未改名的用户仍可使用已有昵称。

### 排错

| 安全日志中的信息 | 处理 |
|---|---|
| pass | 该次真实请求获通过；还需确认手机实际建房/加入及其他玩家看到的昵称 |
| blocked | 已拦截；更换昵称，不通过关闭审核解决 |
| CHECK_ERROR / 权限相关数字错误码 | 核对 `/wxa/msg_sec_check` 权限、开放接口服务开关、新版本是否在开启后创建、环境归属是否为当前AppID |
| 45009 / 44991 | 日/分钟额度限制，稍后按官方额度恢复；不能降级放行 |
| 61010 / 40003 / 43104 | 用户访问记录过期、身份无效或AppID不匹配，关闭后从新版微信体验入口重新进入并核对环境所属账号 |
| TLS_FAILED | 保留已验证的 CA 安装与 NODE_EXTRA_CA_CERTS，检查平台证书挂载，不禁用证书校验 |
| NICKNAME_LOGIN_REQUIRED | 仍在用旧客户端改名；重新上传/选择新版体验包后重新进入 |

自建服务器可显式设置 `WX_CONTENT_SECURITY_MODE=access_token`，使用 `WX_APP_ID/WX_APP_SECRET` 获取 stable_token（该方式也是不使用 Docker 时的默认模式），进程内合并并发请求并缓存，令牌失效只重新获取一次、不强制刷新全局令牌。若报40164，需管理员在微信后台配置服务器出口IP白名单。当前云托管建议用上面的 cloudrun 路径。

## 验收证据与边界

自动测试覆盖风险/待复核拒绝、失败不落库、身份冒用/伪造审核字段、未知结果/超时/TLS/额度错误、稳定凭证缓存及重试、旧昵称迁移、前端改名 code、失败不建房和原有规则回归。详见 `docs/evidence/2026-10-08-nickname-security.json`。

此次本地实现与测试不包含真实微信内容安全 API 联调、管理员后台授权、云端部署、手机风险样例或重新提审。这些须按上面的步骤完成并补录证据。模拟接口测试不宣称微信实际判定准确率，也不能替代审核通过通知。

本次只处理文本昵称，没有新增聊天室/签名/个人空间，也没有声称完成图片审核。固定猫狗素材和原有微信头像路径未变；未来开放自定义图片上传需另行接入图片/多媒体审核。隐私说明应如实补充：为内容安全目的，将用户提交的昵称及对应微信身份标识交由微信内容安全接口检测，只有通过后才向其他玩家展示。

可在完成真实验收后用于平台整改说明：

> 已为自定义昵称接入服务端微信 msgSecCheck v2 内容安全检测。昵称首次提交及修改均先审后存，仅通过结果允许展示；违规、疑似风险和检测异常均拦截，检测失败不覆盖已审核资料。旧版未经审核昵称已做安全替换。服务端不信任客户端审核标记，并保留不含昵称原文及凭证的检测结果日志。
