# 对局记录入口实施计划

**Goal:** 按用户指定，在游戏右上角保留设置并新增同款眼睛按钮，查看本局完整过往记录。

**Architecture:** 复用现有history窗口和共享控制器。后端保留本局公共/每人私密日志；投影仍仅传本人私密记录。前端统一按事件ID排序，牌局变化继续更新记录但不关闭窗口，换房/重开清除旧窗口。首页与等待页保持单设置按钮。

**Tech Stack:** Node.js规则引擎，微信小游戏Canvas2D，WXML兼容页，浏览器HTML/CSS。

- [x] 覆盖超过30条公共/8条私密记录的保存与投影隔离；覆盖记录窗口的阶段变化及换局复位；覆盖五屏按钮点击与边界。
- [x] 移除引擎日志截断；共享derive提供排序后的history，不增加其他玩家私密资料。
- [x] Canvas右上角增加44px圆形眼睛描边图标，保持设置坐标/样式，标题避让；记录窗口复用圆角样式，关闭按钮固定且内容可滑动。
- [x] 浏览器与WXML增加相同入口，移除原页面底部重复记录，保持两端行为一致。
- [x] 相关自动回归、语法/包体、五屏生产渲染与长记录滚动验证；更新当前设计、需求、验收与部署记录。
- [x] 保存GitHub版本并同步已授权的腾讯云测试后端；不把测试部署记为微信上线。

本次沿用用户批准的Apple浅色和温暖猫咪牌桌。记录为本局公开行为加本人的私密记录，以事件序号表示先后；查看不暂停游戏，不公开别人的抽牌内容/插回位置。已被旧版本截断的历史无法恢复，升级后已有局从保留的记录继续累积，再开一局从开局完整保留。
