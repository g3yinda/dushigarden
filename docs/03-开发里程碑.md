## 任务顺序与验收责任

规则变更先确认行为：牌库/开局 → 回合/胜负 → 危险牌 → 攻击债务 → 私密选择/组合 → 否定层与并发 → 超时/恢复 → 公私投影。服务端验证是最终裁决，客户端只提交意图，不决定牌序。

房间验证：独立身份 → 席位/准备 → 并发开始 → 命令去重/状态版本 → 长轮询/心跳 → 重连/快照 → 定时托管 → 离开/关房 → 重启恢复。当前单实例原子JSON快照，不支持多worker共享文件。

页面验证覆盖0/1/8/15张手牌、2/5/6人、长昵称、小屏、安全区、不可用/选中/多选、响应与断线状态。基础13种牌面＋扩展6种＝19种，普通猫五种分别计数。生图仅负责原创插画，动态中文、规则、数字、按钮均由组件绘制。

公开行动按事件顺序展示5秒；正常状态同步不丢失队列，换房或换局清理旧提示，重新进入不重放过去事件。展示不决定规则时钟、不会重复发送操作。减少动态保留同等文字与展示时间。

## 版本维护与后续小游戏

GitHub主分支与版本标签同步代码、当前需求/规则/设计、测试和验收记录；密钥、私有配置、对局快照、输出截图不进入仓库。部署保留数据卷、现有访问码和隧道，升级前保存受控快照及可回滚旧容器。

后续游戏复用身份、房间、邀请、重连和结果能力，添加独立规则模块和页面；当前仍有炸弹猫专用命令，不宣称已完成通用插件平台。新整体视觉风格须再次确认。

历史初始M2–M7估算19–30个有效工作日仅为2026-09-30规划，不含外部备案/审核等待，不是上线日期承诺。早期详细实施计划保留在历史文档目录。
