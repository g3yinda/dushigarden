# 设计与动效任务书

v0.3｜2026-09-30｜已选 Apple 浅色 + 可爱猫咪

## 1. 交付定义

使用 GPT 内置生图制作竖屏页面效果图、原创猫咪和卡牌视觉参考，补充动效分镜与时序。此阶段不写游戏代码。Demo 使用示例状态，不标为已实现联机。用户因费用原因明确要求本项目今后不使用 Canva；不再生成、编辑或维护 Canva 稿。

区分三种成果：静态页面 / 按顺序观看的动效演示 / 真正点击可操作的游戏。本阶段已有静态效果图、动画设计说明和 36 秒可播放样片；尚无可点击原型。样片用 GPT 原创牌面在本地合成，生图本身不生成运动。

GPT 生图输出是位图，不能承诺可编辑的文本/图形图层或可播放动画。正式开发时，中文牌名、规则、数字和按钮用原生文本绘制；生图只作为布局参考和插画来源。生成图中的错字、示意状态偏差必须单独核查，不能作为游戏规则裁决依据。

## 2. 设计原则

1. 大牌名 + 唯一作用图标 + 一句白话效果 + 时机标签。
2. 不读插画也能理解，不只靠颜色区分。
3. 同功能的牌使用一致符号和布局；普通猫必须有五种不同名字和图形。
4. 最终产品的牌面正文须是独立文本，不把生图里的小字直接当生产文案。牌背统一，不暗示功能。
5. 小手牌只负责识别；点按后大卡负责理解；选中后再确认出牌。
6. 不使用官方游戏猫形象或苹果标志。以原创圆润猫咪、细腻柔光和舒适留白表达可爱；字体用系统可用或许可明确的字体。

## 3. 页面清单

| 页/状态 | 必须出现 | 主操作 |
|---|---|---|
| 小游戏大厅 | 平台名（暂名朋友局）、炸弹猫、2–5 人、简短玩法 | 进入游戏 |
| 游戏入口 | 创建房间、加入房间、看规则 | 创建房间 |
| 等待房间 | 房间号、2–5 席、昵称、准备、规则摘要、邀请 | 准备 / 房主开始 |
| 对局桌面 | 自己手牌、其他人牌数、牌堆数量、弃牌、当前玩家与余债 | 选牌 / 抽牌 |
| 卡牌详情 | 完整牌面、作用、时机、可用原因 | 使用 / 关闭 |
| 组合与目标 | 同名选牌、数量、模式、合法目标 | 确认组合 |
| 否定链 | 谁对谁做什么、当前效果会否执行、倒计时、已出否定数 | 否定 / 等待 |
| 被索要 | 谁向我索要、自己的牌可选 | 交出所选牌 |
| 预知 | 三张编号 1/2/3、仅自己可见、不能改序 | 看好了 |
| 抽到炸弹 | 炸弹图形、有无拆弹、不可否定说明 | 使用拆弹 |
| 插回 | 距牌顶位置、最顶/中间/最底、仅自己可见 | 确认放回 |
| 出局/结算 | 爆炸结果、封存提示、胜者、再来一局 | 等待 / 再来一局 |
| 重连/托管 | 正在恢复、服务器当前状态、托管提示 | 恢复后继续 |

对局示例用 4 人：你、小雨、阿橙、木木；人数不代表首版仅支持 4 人。

## 4. 卡牌美术和文案

| 牌面 | 图形建议 | 首层文案 | 详情补充 |
|---|---|---|---|
| 炸弹猫 | 猫与爆炸星形 | 抽到就爆炸，拆弹可保命 | 立刻处理；不可否定 |
| 拆弹 | 猫与剪线工具 | 抵消爆炸，秘密放回炸弹 | 只在抽到炸弹时使用；不可否定 |
| 攻击 ×2 | 双箭头指向下一席 | 不抽牌，让下家行动 2 回合 | 受攻击时：转移剩余回合，再加 2 |
| 跳过 | 跨过一张牌的箭头 | 不抽牌，结束 1 个回合 | 被攻击时只减少 1 回合 |
| 索要 | 伸手接牌 | 选一人，让对方给你 1 张牌 | 对方决定给哪张 |
| 洗牌 | 交叉箭头和牌叠 | 打乱剩余牌堆 | 不会结束你的回合 |
| 预知 ×3 | 眼睛和三张编号卡 | 偷看牌顶 3 张，顺序不变 | 仅自己可见；仍需继续回合 |
| 否定 | 叉号印记/制止手势 | 取消待生效动作，也能反否定 | 不能取消抽牌、炸弹或拆弹 |
| 普通猫 ×5 | 困困猫/饭团猫/宇航猫/侦探猫/摇滚猫，暂定原创名 | 同名 2 张：随机偷 1 张 | 同名 3 张：点名索取；单张无效果 |
| 统一牌背 | 原创猫剪影与简单几何纹样 | 无功能文字 | 任意牌背一致 |

13 种牌面、1 种牌背。七种功能牌：拆弹、攻击、跳过、索要、洗牌、预知、否定；炸弹另计。

文字用近黑色，交互用统一蓝色；插画可以使用 DESIGN.md 允许的低饱和辅助色。不同普通猫的名字不能仅有颜色差别。

## 5. 动效清单与实现约束

以下时间为设计建议，不代表动画已经制作或真机已经实现。

| 动效 | 建议时长 | 起止与要表达的含义 | 降级 |
|---|---:|---|---|
| 选牌 | 120–180ms | 牌抬高、清晰边框，确认区出现 | 直接高亮 |
| 放大详情 | 180–240ms | 从手牌位置进入大卡，文字稳定 | 淡入 |
| 出牌 | 250–350ms | 牌进入桌面，随即进入“等待否定” | 静态置入 |
| 安全抽牌 | 300–450ms | 牌背离堆，只有本人揭面，手牌数更新 | 数量变化 |
| 攻击 | 350–500ms | 下一位头像被指向，准确显示 2/3/4 回合 | 箭头+数字 |
| 否定/反否定 | 200–300ms | 原动作显示取消或恢复，剩余响应时间重启 | 结果文字 |
| 洗牌 | 450–650ms | 不同牌背交错后归位 | 洗牌完成提示 |
| 预知 | 250–350ms | 三张编号卡依序展开，明确私密 | 静态三张 |
| 炸弹与拆弹 | 700–1000ms | 短促警示 → 剪线 → 安全状态 | 无闪烁结果页 |
| 插回 | 250–400ms | 本人确认位置后牌背入堆；他人只见泛化动画 | 已放回提示 |
| 出局与胜利 | 600–1000ms | 头像变出局状态/胜者出现 | 静态状态 |

禁止快速全屏闪烁；声音和震动可关闭；所有关键结果用文本重复表达。演示中如果为了看清放慢时序，要写“演示慢放”，不能让观看者误认 5 秒响应窗已缩成 0.5 秒。

## 6. 首版演示脚本

A. 进入朋友局 → 创建炸弹猫房间 → 邀请/准备 → 桌面，说明抽牌在最后。

B. 选中攻击 → 出牌到桌面 → 显示下一位需要 2 回合 → 对方否定 → 攻击取消、仍轮到自己。另用对照状态展示反否定后攻击恢复。

C. 预知发现顶牌炸弹 → 仍决定抽牌（为演示）→ 拆弹 → 私密选择插回位置 → 结束当前一个回合。

D. 两张同名随机偷牌与索要由对方给牌并列展示；三张组合“点名拆弹”说明失败也消耗材料。

E. 出局和结算 → 再来一局。演示用固定场景，不假装该剪辑是一局经过严格连续模拟的完整对局。

## 7. 资产交付与验收

设计阶段交付页面效果图原图、牌面总览、提示词与版本记录、动效分镜和时序。生产资产阶段再按单牌导出清晰插画（建议 600×900 或同比例高分辨率）、牌背、透明图标；不把多牌总览误称为已切分可用资产。可播放动效样片单独制作和验收。

设计生成后逐图核查中文字、牌名、人数、攻击余债、否定禁区、私密性。仅查看封面不能验收整套。

以手机实际尺寸检查：不放大时能读牌名和识别作用，点开后能读完整规则；手牌 0/1/8/15 张、2/5 人、长昵称、等待响应、断线均有处理方案。

交付状态与实际本地图像路径在制作后补入[来源与决策记录](06-来源与决策记录.md)，未完成资产明确列出。
