# 第一版验收记录

2026-09-30，v0.1.0。本记录区分自动测试、本地实际联调和未验证项目。

## 自动验证

- `npm test`：42 项通过、0 失败。规则 14 项、房间 9 项、HTTP 5 项、完整对局模拟 4 项、客户端行为 10 项。
- 2/3/4/5 人各 25 局，共 100 局自动完整对局：过程中核验牌数守恒、炸弹与存活人数关系、对手手牌隐藏及最终胜者。不是 100 局朋友人工试玩。
- `npm run check`：源码语法、页面文件、AppID 格式、资源与双端控制器一致性检查通过；小程序源码包约 1.18 MiB，不代表微信上传后的精确压缩包大小。
- 攻击余债、否定奇偶链、拆弹插回、预知顺序/隐私、索要、对子/三张、非法指令不改变状态、阶段超时、单席位与重复指令、持久化恢复、损坏单局中止均有测试证据。
- 服务端专项复核发现损坏对局快照可能影响恢复，已修复为仅中止对应局并保存诊断标识；测试覆盖。

## 实际联调

本地 Node.js 24.15.0，服务地址 `127.0.0.1:8787`。微信开发者工具 2.02.2609231 RC，基础库 3.17.3，iPhone 12/13 模拟器；浏览器手机视口 390×844。两个独立身份“阿橙”和“小白”，测试房间 372872。

| 场景 | 实际结果 |
|---|---|
| 微信原生项目导入及编译 | 页面运行，最新编译 Errors:0；5 条工具/基础库警告，未出现业务编译错误 |
| 浏览器建房，微信加入 | 同一房间同步昵称与人数，两个身份各占一席 |
| 双方准备、房主开局 | 两端同步进入对局，2 人各 8 张起手、牌堆 35 张 |
| 选牌与确认 | 浏览器预知牌需先选中再确认，提交后手牌扣减并进入否定窗口 |
| 跨端攻击/否定 | 浏览器打出攻击，微信端打出否定；两端显示奇数层取消，弃牌不退回 |
| 自动流程与结算 | 第一局经过超时抽牌、拆弹、秘密插回，最终小白出局、阿橙获胜；两端显示同一胜者 |
| 再来一局 | 房主操作后，两端回准备页，重新准备并成功开局 |
| 暂时离开与返回 | 浏览器和微信均能回大厅，再返回相同房号/原手牌，未新开身份或新局 |
| 服务重启 | 保存的同一对局可恢复；停服期间出现连接失败，启动后两端重新同步 |
| 手机视觉 | 390×844 检查头像、圆角、牌面裁切、名称/短说明、横向手牌、主按钮；调整微信按钮默认样式和牌面裁切 |

微信工具警告包括灰度基础库、开发模式域名检查、预加载与工具 worker 能力；发布前必须按运行说明恢复域名检查。重启服务产生的历史 connection refused 日志属于停服窗口，最新重新编译后 Errors:0。
