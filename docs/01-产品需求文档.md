# 朋友小游戏平台 · 炸弹猫 PRD

版本 v0.10.12 客户端实施基线｜2026-10-03

## 1. 产品目标

朋友在微信中邀请彼此，进入同一房间玩一局炸弹猫。新手不必先读长规则，每一步都能知道“现在轮到谁、这张牌做什么、我可以怎么操作”。平台后续加入其他小游戏，共用身份、邀请、房间和结果页。

首版成功标准：2–6 人能够独立建房、加入、准备、开始、完成对局及再来一局；裁决一致；对手看不到不该知道的牌；短暂切后台或断网后能继续；牌面作用易理解。

## 2. 已确认与规划假设

已确认：2–5 人基础版，6 人完整内爆猫扩展；Apple 浅色 + 可爱猫咪；GPT 内置生图设计；先文档与 Demo 后代码；GitHub 仓库 g3yinda/dushigarden 已提供并用于版本维护。

当前已实施基线：好友私密房、中文竖屏、启用同名对子和三张组合、不开五张不同组合、30 秒行动预算、否定响应 10 / 20 / 30 秒或不限时（默认 10 秒）。完整数值和异常规则在规则文档中定义。

“微信小程序”是用户的微信入口需求。2026-10-03 新 AppID `wxf7af6d01a9bbfdbd` 在工具中仅提供小游戏模式，用户明确授权迁移：当前客户端改为微信小游戏 Canvas2D 运行环境，保持原有好友房、规则和已批准设计。编译运行不证明已完成备案、游戏类目材料、审核或发布。

## 3. 范围与方案比较

| 方案 | 内容 | 优点 | 代价 | 建议 |
|---|---|---|---|---|
| A. 基础版完整好友房 | 2–6 人，固定规则，2–5基础牌，六人完整内爆扩展及组合牌 | 可玩性完整，争议少，可扩展 | 需要正确实现否定窗口和重连 | 首选 |
| B. 教学精简版 | 暂不做三张组合等进阶玩法 | 更快验证操作 | 规则不完整，之后需改教程 | 可用作教程，不作为正式规则 |
| C. 派对/扩展版一起做 | 更多玩家、更多牌、可选规则 | 一开始内容多 | 规则分叉和测试成本高 | 推迟 |

P0：大厅、炸弹猫介绍、创建/加入房间、微信分享入口、房间码备用入口、准备、规则说明、完整基础对局、手牌详情、组合出牌、断线重连、托管、胜负结果、再来一局、音效和减少动态开关。

P1：本地教程进度、短期最近战绩、房间固定表情、更多小游戏入口、在实测后调整节奏。

暂不做：公开匹配、段位、支付、押注、语音聊天、好友关系系统、无限自定义规则、其他扩展包、高级 AI 对手、旁观者查看手牌、完整可分享的私人对局回放。没有第二个已完成游戏时不放可点击的虚假游戏入口。

## 4. 用户故事

| 编号 | 角色与需求 | 验收目标 |
|---|---|---|
| US01 | 玩家想看到可玩的小游戏 | 大厅显示炸弹猫、人数和简短规则 |
| US02 | 房主想快速邀请朋友 | 创建房间后能分享；分享失败可用房间码 |
| US03 | 好友想从邀请进入正确房间 | 显示房主、人数、是否已开始，错误可恢复 |
| US04 | 玩家想知道规则再准备 | 房间展示固定规则摘要，完整规则随时查看 |
| US05 | 房主想等所有人准备好 | 至少 2 人、至多 6 人，全部准备后才能开始 |
| US06 | 玩家想看懂手牌 | 点按放大，显示作用、对象、出牌时机、是否结束回合 |
| US07 | 玩家想避免误出牌 | 选牌不等于提交；可取消，合法后才能确认 |
| US08 | 玩家想知道为什么不能出 | 禁用原因明确：非自己回合、数量不足、等待结算等 |
| US09 | 玩家想使用攻击和跳过 | 显示精确剩余回合数和转移对象 |
| US10 | 玩家想否定别人的操作 | 响应窗口可见，有效否定同步给所有人 |
| US11 | 玩家想偷偷查看未来 | 只本人收到牌序；其他人仅知道使用了预知 |
| US12 | 玩家想自己决定给出哪张牌 | 索要结算时由被索要者选择；不泄露其余手牌 |
| US13 | 玩家想用对子/三张组合 | 明确切换组合模式、选择合法对象和目标牌名 |
| US14 | 玩家抽到炸弹后想使用拆弹 | 有拆弹进入处理，无拆弹出局；不可插入其他行动牌 |
| US15 | 玩家想秘密放回炸弹 | 以距牌顶的位置选择，其他人不能看到位置 |
| US16 | 玩家临时切到微信聊天 | 回来恢复当前状态，不重复发牌或重播过时秘密信息 |
| US17 | 大家不想被断线者卡住 | 阶段超时有公开且一致的托管规则 |
| US18 | 出局者想等朋友打完 | 仅看公共桌面和结果，不暴露存活者手牌 |
| US19 | 大家想继续下一局 | 原房间重新准备，新牌库和新对局编号 |
| US20 | 用户未来想增加其他游戏 | 平台能力和炸弹猫规则可以独立扩展 |

## 5. 端到端流程

大厅 → 炸弹猫 → 创建房间 / 输入房间码 / 从邀请加入 → 等待和准备 → 全员准备后房主开始 → 洗牌发牌 → 回合行动 → 抽牌或跳过/攻击 → 爆炸/拆弹处理 → 最后一位存活者获胜 → 结果 → 再来一局或回大厅。

### 当前玩家体验

- 建房先显示设置，“出牌不倒计时”默认关闭。开启后行动、索要交牌、预知确认、调整未来、拆弹和秘密插回均不限时，否定响应可选每层 10 / 20 / 30 秒或不限时，默认 10 秒。每次否定或反否定重新计时，再开沿用，进行中不可改规则。
- 否定选择固定在页面底部的打出/抽牌操作栏上方，显示“是否选择否定”，不再自动弹窗。点击“本次不出”由服务器确认，本轮不可改为打出，本人停止计时并显示等待人数；全部持牌响应者确认或超时后结算，选完可提前结束。没有否定者自动完成，两个按钮置灰且不计入等待；持牌 Bot 同样确认。无人能响应时直接结算。“可循环否定”默认开启，每张否定开启新的反否定响应层，其他仍持否定的玩家可以重新选择；关闭时首张否定取消原动作且不再开层。倒计时以剩余秒数和细进度条展示，最后 3 秒加暖红与文字提示。
- 所有玩家围坐同一张浅暖椭圆牌桌，本人下方；桌中央放牌堆、真实弃牌和当前阶段。
- 手牌平时重叠，可左右滑动；用紧凑浅蓝胶囊“展开手牌 / 收起手牌”切换，触控区域至少 44px；点选抬起并展开，可单选或多选。先选牌，后点下方打出，再在居中弹窗选择头像/姓名目标并确认。取消不丢牌。
- 出牌展示 5 秒，显示出牌者、牌名与组合张数；多个公开事件排队，普通同步不清空。
- 不限时在线玩家不会被自动代选；离线或主动退出后按原阶段时长托管，恢复在线取消未执行的托管。全体真人离线 5 分钟中止。
- 本地验证 Bot 可添加 1–5 只，无付费模型，正式微信模式不提供该入口。

### 房间约束

- 房间码用于定位房间，不作为身份凭证。席位与服务端认证身份绑定；同账号不重复占座。
- 房间码为 6 位数字，限制失败加入频率；微信分享入口携带房间号，真实分享与微信身份联调仍待验收。
- 待开始时允许离开、房主移除席位和重新加入；人员变化取消真人准备状态，Bot 自动准备。
- 满员、房间过期、已开始均显示具体原因。首版不接受陌生观众或中途补位。
- 待开始房间空置 30 分钟关闭；对局中房主选择“仅自己离开”不销毁房间；选择“关闭整个房间”经居中二次确认后终止，不产生胜者，全员返回大厅并可另建房。房主离开后由最早加入的在线成员接任管理角色。
- 对局中房主无改牌、看牌、回滚、踢出存活玩家的权限。
- 开始按钮以服务端原子条件裁决，避免同时开始两局。规则及牌库版本随对局冻结。
- 再来一局：创建新的对局实例，保留仍在房间的成员，真人重新准备、Bot 自动准备；上局手牌不复用。

### 页面与状态

大厅、游戏介绍/规则、加入房间、等待房间、对局桌面、卡牌详情、组合选牌、目标选择、否定响应、索要交牌、预知私密展示、炸弹处理、秘密插回、出局等待、结算、重连遮罩。

对局桌面始终显示：房间、存活人数、座位顺序、各人手牌数量、当前玩家、剩余回合、牌堆张数、最后公共行动、自己的手牌、一个明确的主操作。

## 6. 逻辑模块与数据边界

| 模块 | 责任 | 输入/输出边界 |
|---|---|---|
| 平台身份 | 验证微信身份并签发会话 | 平台身份 → 服务端玩家标识 |
| 游戏目录 | 展示启用游戏、入口及版本 | gameId → 展示配置及入口 |
| 房间服务 | 邀请、席位、准备、开始、再开 | 玩家命令 → 房间公共状态 |
| 炸弹猫规则引擎 | 所有合法性、牌序、回合与胜负 | 权威状态 + 命令 + 随机源 → 新状态 + 事件 |
| 状态投影 | 分离公共与私人信息 | 权威状态 + 接收玩家 → 该玩家可见数据 |
| 联机同步 | 命令去重、事件排序、恢复连接 | 序号/命令标识 → 事件或快照 |
| 前端交互与动效 | 表达意图和展示服务端结果 | 可见状态 + 用户点击 → 命令 |
| 运行维护 | 诊断失败、记录版本和错误 | 脱敏日志、指标；不记录公开可访问的完整牌序 |

已采用服务端权威房间模型、HTTP 长轮询同步与原子 JSON 快照，单实例 Node.js 24；腾讯云 Docker 提供受控公网测试。不要把客户端本地存储作为真实牌库或胜负来源。无需在第一版开发通用插件引擎；预留游戏标识、规则版本和标准命令接口即可。

核心实体：玩家、房间、席位、对局、规则快照、卡牌实例、抽牌堆、公共弃牌堆、封存区、待结算行动、响应链、阶段截止时间、公共/私人事件、结算结果。

每个命令带唯一命令标识、对局标识、预期状态版本、当前阶段/行动标识；玩家身份从服务端会话获取。重复命令只返回原结果；旧版本请求要求重新同步，不重复扣牌。

## 7. 隐私、公平与体验要求

- 对手手牌、抽牌堆顺序、炸弹插回位置、未公开封存牌不得下发给非授权客户端。
- 即便前端不显示也不能把全量状态发送到设备。分享图片、错误日志、分析事件同样不能泄露私密牌面。
- 随机洗牌和偷牌均在服务端完成；客户端不能提交随机种子决定胜负。测试可以使用可复现随机源，生产种子不公开。
- 被索要者、偷牌双方可知实际转移牌；其余玩家只知转移张数。公开三张组合时声明的牌名可进入公共日志。
- 第一阶段只显示公共行动历史，不实现私人全局回放。
- 动画与服务器时钟分离；动画慢不应延长或吞掉玩家的合法操作窗口。
- 界面目标：新手看放大牌面后 5 秒内说出主要作用；5 位试玩者中至少 4 位可无口头指导完成常规回合。属于验收目标，尚未测试。
- 性能目标：普通网络下指令确认 P95 ≤ 800ms；回到前台后 3 秒内恢复状态；关键动画常见手机力争 50fps 以上、弱设备降级不阻塞操作。需记录设备和网络条件后实测，不能作为现状宣传。

GitHub 已接入 main 与版本标签：文档版本、规则版本、资产版本、代码版本分别可追踪。凭证进入平台密钥管理，不能提交仓库。生成原图、提示词和资产清单与代码一同维护；不把当前下载的官方说明书或卡图当作自有资产上传。

当前快照保存会话、房间及恢复所需对局；等待房全体真人离线30分钟清理，进行中全体真人离线5分钟中止，非进行中房间全体真人离线24小时清理；主动关闭的房间5分钟后移除。计时从全员离线起算，不是固定完成后24小时；未实现技术错误7天清理或长期战绩，正式发布前需确定保留策略。

当前已按用户授权实现本地可运行版，公网测试后端已部署；真实手机、微信登录/分享和正式发布仍待验收。需求变动与规则适配同步记录并验证。


## v0.8.0 六人自选扩展

建房提供两个独立布尔开关“加入内爆猫”“加入反转”，默认开启，只在六人开局启用扩展时生效；2–5人仍基础版。关闭项不进入牌库/手牌/可声明索牌目录。关闭内爆以5张普通炸弹保持唯一胜者，关闭反转移除4张；其余四种扩展保留。设置公开给同房玩家，建房后固定，再开沿用；旧对局不改牌库。具体验收与数量表见规则文档第7节。

## v0.9.5 布局与信息要求

首页与建房弹框按手机可用高度一屏显示，建房不可上下滑动，全部规则仍可设置，创建48px高、控件至少44px、底部留白。等待房每行两人；头像完全在牌桌内；手牌重叠与取消/展开同款胶囊，否定和动作共同固定底部。页面去除重复教学、方向、桌面版本及闲置响应说明，仅按需显示选牌详情或错误原因；出牌5秒与抽弹姓名提示保留。


## v0.10.2 对局提示与选择

Canvas小游戏被索要牌时仅在手牌范围提示索要者，选择一张后由固定底部交牌；牌桌、手牌信息和固定位置保持可见。其他对局选择在独立居中弹框内一屏完成；点名同框分页，秘密插回采用位置步进与快捷位置。退出确认优先并持续保留，规则及服务器命令不变。具体布局与实际验证分别见设计任务书、验收记录。


## v0.10.6 当前提示与动效补充

新牌提示显示真实获得者姓名、头像和牌名，仅向本人展示；预知/调整未来私密说明内嵌选择框，不再重复提示。牌桌头像及姓名按可用尺寸放大，手牌及底栏固定。抽炸弹时播放一次2.8秒全画布暖色爆炸，包含冲击波、火光、碎片和烟团，身份提示仍5秒；动效避开选择弹框和提示卡，拆弹可直接操作。减弱动态保留静态提示，不改变抽牌、拆弹或插回规则。具体尺寸、效果层次、实际验收范围分别见DESIGN.md、设计任务书及验收记录。

### v0.10.8 对战场景与手牌

用户批准温暖猫咪房间背景及奶油椭圆桌；当前Canvas小游戏采用较大围坐头像和牌堆，折叠手牌展示小牌名、插画、分类色猫爪，至少44px露出区域，横滑/多选/选中展开/详情保留。桌面、手牌、否定与动作底栏固定一屏，按窗口/微信胶囊/安全区适配；规则、资格、超时与私密流程不变。既有分类色沿用，原浏览器和WXML不在本轮改版范围。详见[实施验收](implementation/cozy-table.md)。

### v0.10.9 行动识别与牌堆

当前行动头像高亮加粗并随回合切换；结束对局不继续提示行动。隐藏牌堆使用原创可爱小猫牌背，图片加载失败不妨碍操作。牌堆与剩余数量稍加间距，危险警示、头像及底部操作不互相遮挡。仅改Canvas装饰和响应式布局，规则与后端不变。
